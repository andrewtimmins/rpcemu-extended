RPCEmu Extended Edition 1.2.0. Fifteen commits since 1.1.19.

A version number rather than a patch because the debugger has grown a great
deal: floating point registers, the banked registers of every processor mode,
and the ability to change the machine rather than only read it. Nearly all of it
comes from one person using the Machine Inspector every day against his own code
and writing down what got in the way.

## The debugger can see the whole machine now

**Floating point registers.** The FPA10 has been emulated since 1.0.1, but the
debugger would disassemble an FPA instruction and then say nothing about what it
did. F0 to F7 now sit beside R0 to R15 in the Machine Inspector, with FPSR and
FPCR in the Status box, and `fpregs` on the debug socket gives the same thing to
a script. Each register comes back twice: the three words the chip actually
holds, in the 80-bit extended format, and the value they stand for. The raw
words are the authority, and they are the same words `LDFE` and `SFM` move, so
they compare directly against a register spill in memory. Asked for in
discussion #257.

**The banked registers.** R13 and R14 of User, FIQ, IRQ, Supervisor, Abort and
Undefined, one mode at a time from a list, with FIQ's own R8 to R12. Stepping
through an exception path means wanting the handler's stack pointer beside the
one the interrupted code was using. The debug socket's `bankregs` returns all
six at once.

**Changing things, not just reading them.** Right-click a register or CPSR to
set it; the memory view has a **Write...** button that takes hex pairs at the
address on screen. Both decline while the machine is running and say so. This
had worked over the debug socket for a while and belonged in the window.

## Reading code in it

- `ADD R1, PC, #&5000` renders as `ADR R1, &00105008`, and a literal pool load
  says what it will fetch: `LDR R0, &10030  ;=&125640`.
- The instruction about to execute is coloured, not just marked with `<`.
- Double-click a register to point the memory view at it. R13 for the stack.
- Double-click any line of the trace to take the disassembly to that address.
- The memory view has a **Words** box, little-endian as the machine stores them.
- The processor mode moved beside CPSR and shortened: `CPSR 40000093  SVC32
  priv`, with SPSR naming the mode it would restore the same way.
- Run, Pause, Step and the machine's state moved out of the Debugger tab and
  into the window, so they are available whatever tab is showing.
- The machine window stays where you put it instead of returning to the centre
  of the screen on every mode change, which made a Reset feel like it had moved
  house. The Machine Inspector reopens where you left it, and a saved session
  now carries the window size and the pane divisions along with everything else.

The Machine Inspector's layout changes are verified on macOS. The Windows and
Linux CI jobs run the emulator but not its window, so if a pane or the coloured
line looks wrong on those, please say.

## Fixes

- **A reserved CPU mode halt named the wrong instruction.** `MOVS PC, R14` and
  `LDM {..., PC}^` change mode and branch in one instruction, and the address
  was worked out from R15 after it had been loaded with the branch target, so
  the halt reported the target minus four. Since those two instructions are how
  a guest usually reaches a reserved mode, it was least useful exactly when it
  fired.
- **A prefetch abort now names the instruction that branched there.** The
  faulting address is by definition one that could not be fetched, so there is
  nothing to disassemble at it; the view opens on the instruction responsible.
- **An abort opens the disassembly on the faulting instruction** rather than on
  the hardware vector. The debugger always knew the right address; the view was
  following R15, which is on the vector by then.
- **Step over on the branch at the bottom of a loop** now steps past the loop
  instead of going round it again.
- **Auto step did nothing when ticked on a running machine**, and said nothing
  about why. It now stops the machine and steps it.
- **`reg set pc` on the debug socket meant a different PC** from every value the
  debugger reports, so setting the PC to an address resumed the machine eight
  bytes below it, and in a 26-bit mode it cleared the flags and processor mode
  that R15 carries. A client that was compensating by subtracting eight should
  stop.
- **The memory view read physical addresses** while every other address in the
  window meant a virtual one, so the disassembly and the memory contents at the
  same address showed different things. Reported as #258.
- **The monitor advertised only the configured screen size**, so a larger mode
  was missing from the list or refused with "This screen mode is unsuitable for
  displaying the desktop". Two people on the forum hit this, one wanting
  1920x1080 and the other 2560x1440. The test that should have caught it was
  built at the largest mode in the table, where the fault cannot occur.

## Downloads

Every archive carries both emulators, on every platform and every architecture,
as it has since 1.1.17. `rpcemu-recompiler` translates ARM code into your
processor's own and is the one to use; `rpcemu-interpreter` executes one
instruction at a time, which is far slower and exactly what you want when
something behaves oddly and you need to rule the recompiler out.

On Windows and Linux the two sit side by side. On macOS the application runs the
recompiler, and the interpreter is inside the bundle at
`RPCEmu.app/Contents/MacOS/rpcemu-interpreter`.

That includes Windows on ARM: the arm64 download is a native AArch64 build of
both, and the recompiler is the one CI boots RISC OS on. Anyone who chose
between the two Windows downloads before 1.1.17, when the arm64 one carried the
interpreter alone, no longer needs to: they differ only by architecture.
