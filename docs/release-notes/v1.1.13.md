RPCEmu Extended Edition 1.1.13. One hundred and eleven commits since 1.1.12.

## The fork has a name

"Spork Edition" was a placeholder that outlived its welcome. The window title,
the application name, the VNC desktop name, the dialogue captions and the About
box all say **Extended Edition** now. Nothing about your machines or settings
changes; it is the same emulator with its own name.

## A debugger you can actually work in

There has been a debugger for a while. It could stop the processor, and not much
else. It can now:

- **Disassemble the FPA**, and describe what an instruction does rather than
  printing a raw word.
- **Stop on a condition**, not just an address: `bp add 8000 if r0 == 0`, with
  `once` and `count n`.
- **Step over a call, step out of one, and show you how you got there** with a
  backtrace.
- **Give addresses names.** Load a symbol file and the names appear in both the
  backtrace and the disassembly.
- **Cost nothing when nothing is attached.** The per-instruction checks are not
  paid for by a machine that is simply running.

`rpcemu-debug`, the command-line client that drives all of this, is now **in
every download**. It has existed since 1.1.3 and was never actually packaged: it
was built and then left in the build directory, so the one thing you needed in
order to use the debugger from a terminal was missing from every platform's
release. See `docs/debugcmd.md`.

## Several machines at once

Running two machines used to mean two guests both convinced they were
10.10.10.10, with the same hardcoded MAC address.

- **Each running machine gets its own address**, guest IP and MAC alike, so they
  are distinct hosts rather than duplicates.
- **Per-instance ports and sockets**, so two machines no longer fight over one
  VNC port or one control socket.
- **A machine refuses to run twice.** Two copies of one machine write to the same
  disc image and the same CMOS, and the damage does not show until ADFS starts
  complaining. The lock is held by the operating system, so a crash cannot leave
  a machine permanently unstartable.
- **A VNC port is only advertised when something is actually listening on it.**

They still cannot see each other over the network. That work is in progress on a
branch, and `docs/multi-machine.md` says where it is going.

## Keyboards match the keys you press

Windows and macOS mapped **characters** to a UK keyboard table, so a key was
identified by what it typed rather than by where it was. That is wrong for anyone
not on a UK layout, and it is why several apparently unrelated reports turned out
to be one bug.

Keys are now identified by physical position on all three platforms. This fixes
German keyboards (#88, hubersn), the third mouse button alternative on macOS
(#91, Astro-mh), and part of the shifted-character problem on macOS (#70,
riscosports). **AltGr is delivered**, which previously reached RISC OS on no
platform at all. The Menu key works on Windows.

Both mapping tables can now be tested from any platform, so a macOS keycode
mistake is caught on a Linux CI runner rather than by a user.

## Where your files live

- **You are asked where the data folder should go** rather than having one
  chosen for you (#67, Septercius).
- **A machine can say where its HostFS drive is** (#77), so a machine can point
  at a folder of your choosing instead of the one beside the binary.
- **Moving either offers to bring the files with it**, and warns when a new
  folder is empty or an absolute path has gone stale. An empty HostFS folder
  means an empty disc, which on RISC OS 5.31 is a bare grey screen and looks
  exactly like a broken machine.

## Full screen, and the window generally

Mostly David Ramsden's work, and mostly things that were quietly wrong:

- **Alt+Enter leaves full screen**, and is passed through to RISC OS when there
  is nothing to leave.
- **The full-screen menu item is ticked while you are in full screen.**
- **The status bar is removed rather than hidden**, so its space is not left
  reserved as an empty strip along the bottom.
- **The window is no longer shrink-wrapped when leaving full screen.**
- The toolbar no longer claims keyboard shortcuts that do not exist.
- The "you are entering full screen" message is now one dialogue with a
  checkbox rather than a double negative.

## Getting help, and telling us what broke

Also David Ramsden's:

- **Help ▸ Report an Issue** and **Help ▸ Check for Update**.
- **Help ▸ create a support bundle**: the log and the machine's settings in one
  zip, optionally with a screenshot.
- The log records **which Windows or which macOS**, not just the family, and
  where the emulator was when it died.
- A bug report template that asks for host, build and RISC OS version.
- The About box renders its credits correctly again.

## Networking

- **EtherRPCEm starts on machines with less than 256MB of RAM** (#101,
  david-ramsden, and the real cause of #2). A card ROM module must not identify
  itself to `Podule_ReadInfo` by base address, because below 256MB the address it
  is looking for is not where it expects. Ask by card number, as Acorn's own
  Econet driver does.
- **Received frames are queued** and transmit has a buffer of its own. Receive
  used to be capped at one frame per poll, which turned a six-fragment ping into
  a 25ms round trip; it is now 0.88ms.
- **The NAT TCP window is no longer 8KB**, which was throttling throughput (#74,
  riscosports).
- A bridged machine gets its own address too.
- The NAT stack is polled per instruction batch rather than per loop, and not
  polled at all before it exists (David Ramsden).

## Other fixes

- **Sound and cursor DMA read the wrong memory on a Kinetic.** Both decoded
  physical addresses themselves, with bit tests that do not recognise the
  Kinetic's SDRAM banks, so both fell through to "SIMM 0 bank 0" and fetched
  unrelated memory. SIMM 1's upper 64MB also aliased onto its lower half.
- **The disassembler shifted a 32-bit value by 32**, which is undefined, on
  almost every data-processing instruction it printed. Found by the sanitiser
  job once a disassembler test existed to trigger it. The result was discarded a
  line later, which is why nothing ever looked wrong.
- **A partial repaint is drawn at the same scale as the whole frame.** Redrawing
  only the invalidated band, added since 1.1.12, scaled each band by its own
  rounded ratio rather than the frame's, so anything the pointer passed over
  appeared to shift by a pixel. Only affects scaled modes: fit to window,
  integer scaling and full screen.
- **The clipboard offers the guest the length it is going to get** (#81,
  riscos-richard), and SyncClock puts back the time zone it was taking off
  (#69, riscos-richard).
- `GfxCard$Display` is a code variable, so ADFFS can read it.
- Two pieces of undefined behaviour the compiler was entitled to get wrong.

## New: the OPEN Bus

The Risc PC's second processor interface is emulated, with a stub card and
`--openbus-stub` to exercise it. This is groundwork rather than something to use:
nothing yet drives a real second processor. The debugger cannot read the card's
window, so a decode test is what proves the wiring reaches a fitted card.

## Under the hood

- **The test suite is enforced.** Configuring fails if the number of tests is not
  the number the build expects, so a suite cannot quietly lose half its cases. A
  pre-push hook builds and runs everything before a push leaves your machine.
- **The Windows suite runs under Wine** on Linux, so the Windows build is checked
  before CI rather than after.
- **CI fails on aborts a screenshot cannot show**, and reports to a Slack channel
  when a build breaks, when it is fixed, and when a release goes out.
- The warnings gate covers code this project maintains, and eleven warnings in it
  were fixed rather than exempted.

## Verified, and not

Every platform's build is checked by CI on every push, and the unit suite,
command-line checks and a real RISC OS boot run on all of them.

Two things in this release want confirming by someone with the hardware:

- **The full-screen layout fix for macOS** is reasoned from what wxOSX does
  differently, not something we have watched happen. It is inert where the
  layout was already correct.
- **The OPEN Bus** has no real second processor to talk to.

Machines still cannot see each other over the network, and the reports of a
sluggish pointer and high CPU on Intel macOS are not fully explained. If you are
seeing those, please say whether turning off Fit to Window and Integer Scaling
changes anything.
