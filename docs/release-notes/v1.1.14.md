RPCEmu Extended Edition 1.1.14. Fifty-three commits since 1.1.13.

## The recompiler works on Apple Silicon and arm64 Linux

The arm64 recompiler has never booted. `--recompiler` on an Apple Silicon Mac or
an arm64 Linux machine crashed, and the only way to run was the interpreter
(#30). Three separate defects, each of which alone was fatal:

- The IRQ test overwrote the register holding the value just loaded, so the
  first interrupt after a load corrupted it.
- A generated block could run past the end of its slot into the next one.
- Block chaining decided where to jump in generated code, without checking the
  target was still valid.

RISC OS 3.71, 4.39, 5.30 and 6.20 all boot to the desktop on the arm64
recompiler now. Verified by booting each one headless and measuring how much of
the screen was drawn, rather than by watching it once.

**A 26-bit correctness fix that affects every backend** (#154). Switching between
26-bit and 32-bit modes left the block cache holding code compiled for the old
word size, so a program that changed mode ran blocks that computed the wrong
addresses. The fix is one place that covers arm64, amd64 and x86 alike, since all
three shared the fault.

## The display is drawn by the GPU

The guest's screen was rescaled on the CPU every frame. It now goes to the
graphics card as a texture (#147). On an Apple Silicon Mac the emulator's idle
CPU use dropped from around 41% to around 36%. It is on by default on all three
platforms and can be turned off if a driver misbehaves.

## Display settings you can reason about

There were four switches - Pixel Perfect, Fit to Window, Follow Host Display Size
and an unnamed default - where two of them scaled the same number of guest pixels,
one changed how many there were, and two of the four silently cleared each other.

There are now two settings:

- ***Settings > RISC OS Screen Size*** - a list of resolutions, filtered to what
  the machine's display memory can hold and what RISC OS actually accepts.
- ***Settings > Show In Window*** - actual size, or whole multiples only.

The window is the size of the RISC OS desktop and is centred with its title bar
always reachable. It no longer follows every mode change as it happens: RISC OS
passes through two or three modes while booting, and with the graphics card the
display is handed over part way through as well, so the window used to jump
through three sizes and positions before settling.

Worth knowing why "follow the window" is not among the choices. RISC OS accepts
only screen modes the monitor definition in force declares, and that is normally
a definition file the guest's own `!Boot` loads rather than the EDID the emulator
synthesises. On one machine with the graphics card fitted, only six of the
thirteen modes that fit its display memory were accepted, and not the ones anyone
would guess: 1920x1200 yes, 1920x1080 no. A size that is refused is now detected,
reported once and taken out of the list. See `docs/display.md`.

## Closing a machine asks first

Clicking the window's close button shut the machine down with nothing asked.
It now asks, and answering yes offers the machine selector, so finishing with one
machine and starting another no longer means quitting and launching again.
`File > Exit`, which is Cmd+Q on macOS, asks the same question - it used to
bypass it entirely.

## The keyboard and mouse on macOS

- **Caps Lock and Command work** (#148, #149). macOS sends no release for Caps
  Lock, and none for an ordinary key pressed while Command is held, so those keys
  were held down for ever from the guest's point of view - which is why Caps Lock
  behaved backwards and Command+L repeated the letter endlessly.
- **The pointer stops fighting you at a screen edge** (#128, hubersn). The guest
  clamps its pointer at the edge while the host pointer carries on; reversing did
  nothing until the mouse had travelled all the way back.
- **The option to capture the mouse in the window is back**, also #128. Untick
  *Settings > Mouse Follows Host Pointer* and RISC OS is given the movement
  instead, so its own mouse speed and acceleration apply. Alt+Enter releases it.
- **An error box no longer traps the host pointer** (#140, zurnedden). RISC OS
  sets a bounding box for an error window and holds its pointer inside it, and
  the emulator was dragging the host pointer along with it.

## ShareFS and Access

Large file transfers were corrupt or stalled, and neither reported anything.

- **A datagram is read whole.** The receive buffer was 8192 bytes and ShareFS
  sends bulk data as 8200-byte payloads, so every data datagram silently lost its
  last 8 bytes. A 64MB file arrived at the right length with around 6000 corrupt
  8-byte runs in it, and no error anywhere.
- **A fragmented datagram now carries the real sender's address.** The
  fragmenting path forged it as the NAT gateway, so a guest's reply went into the
  NAT network and the peer never heard it. Every Access datagram over 1472 bytes
  took that path.
- **Acknowledgements get back before the sender gives up and resends**, and the
  relay no longer throttles transfers.

## Packages

The package database was at `$.!Packages`, which no RISC OS tool looks in.
PackMan and RiscPkg keep theirs in `!Boot.Resources.!Packages`, and HardDisc4
ships PackMan, so a machine could have two databases with each manager
overwriting files the other believed it owned and neither able to uninstall the
other's packages.

RPCEmu now shares theirs. An existing database is used as it is, one already at
the old location is merged and then renamed rather than deleted, and a package
recorded in both keeps the shared record. A manifest's leading path components
are also treated as logical paths at last, so a package naming
`Resources.!PythonSite` lands in `!Boot.Resources` instead of in a `$.Resources`
that nothing looks at. Each package's licence is shown in the manager.
See `docs/packages.md`.

## Windows on ARM

There is now a native arm64 Windows build, produced and boot-tested by CI
alongside the others.

## Also in this release

- **A redesigned Machine Inspector**: registers, status, disassembly and memory
  visible together, with changed values highlighted.
- **Read-only VNC authentication** - a second password for clients that may watch
  but not type. Contributed by **Charles Ferguson**.
- **A manual and a quick start guide**, and the host interface documentation
  (HostFS, HostCmd, the clipboard and the network SWI) written up in PRM-in-XML
  and published with each release. Largely **Charles Ferguson's** work.
- **EtherRPCEm is built from assembler on the host**, so the guest network driver
  is no longer a committed binary nobody can rebuild. **Charles Ferguson**.
- **HostFS**: a host file with no type gets one from its extension, and a rename
  that would produce a leaf of "." or ".." is refused.
- **Each machine gets its own log again**, rather than sharing one.
- A CD-ROM handle is forgotten on eject rather than only on close, the NAT
  transmit path is bounded against the chain the guest built, and HostCmd answers
  a command when no guest module is there to collect it.
- macOS declares local network use, so the system can grant it.
- The **MCP server's documented setup works**, and is checked by CI so it keeps
  working. **David Ramsden**.
- **CI is a chain of gates** rather than a flat run, so a failure points at what
  actually broke. **David Ramsden**.

## What is not proven

These notes are only worth anything if they say where the testing stops.

- **The display, mouse, keyboard and window changes were written and tested on
  macOS.** CI compiles and boot-tests them on Linux and Windows, but the
  behaviour has not been exercised there by hand. #128 and #140 were both
  reported on Windows 11 and fixed without a Windows machine to try them on.
- **#140 is still open.** The mechanism is fixed, but the reporter's central
  observation - that it happens while the RPCEmu window is *not* the active one -
  is not accounted for, and closing it on a partial explanation would be wrong.
- **The recompiler work was verified on arm64 macOS.** The same fixes were applied
  to the amd64 and x86 backends, where they are compiled and tested by CI but the
  boot was not repeated by hand on those hosts.
- The graphics card and the OPEN Bus co-processors remain new and lightly used.
