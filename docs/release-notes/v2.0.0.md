RPCEmu Extended Edition 2.0.0. Two hundred and ninety-seven commits since 1.1.15.

A major version because the shape of the application has changed. 1.x is one
machine in one window. 2.0 is a Manager with a list of machines, several of them
running at once, able to see each other over a network of their own. The 1.x
line continues: 1.2.0 was released alongside this and carries the same debugger.

## The Manager

A list of your machines, with what each one is doing: stopped, starting,
running, suspended. Start several and switch between them. Each machine is its
own process, which is not a workaround but the point: one machine crashing,
being suspended or being stepped in the debugger leaves the others alone, and
the Manager stays up whatever any of them does.

A machine can be drawn inside the Manager window or given a window of its own.
Suspend and resume are on the toolbar, so a machine can be put down mid-session
and picked up later. Closing a machine leaves the Manager and every other
machine exactly as they were.

Machines can also be started directly, from a desktop shortcut the Manager
writes for you, without going through the list at all.

## The machines can see each other

Every machine sits on a private network behind its own NAT, is given an address
by DHCP, and gets its own MAC address. Addresses are derived from that MAC on
`100.64.0.0/10`, so two installations that have never met agree about who is
who, and the emulator says so when two machines compute the same address rather
than leaving you to find out from RISC OS.

**A virtual switch** connects the machines you are running, so ShareFS discs,
printers and anything else RISC OS does over a local wire work between them,
with no server involved at all.

**JSON networking** carries a machine's Ethernet over a TCP connection to a
network server. The protocol and its server are Charles Ferguson's, written for
RISC OS Pyromaniac, which has spoken it for years, so a machine here and a
Pyromaniac elsewhere can reach each other. It has been in RPCEmu Extended for a
while under the name Pyromaniac networking; 2.0 renames it for what it is, gives
every machine its own MAC address, keeps the setting when the machine is
running, stops a server that never answers from holding up a boot, and
reconnects rather than giving up.

**The Community Network** is one shared network anybody running RPCEmu Extended
can join. Tick one box in the machine editor; there is nothing to configure,
because the server is already running at a fixed address and everybody who turns
it on lands on the same wire.

What is on it is the point. A ShareFS server offers discs anyone can mount, and
because it is one network rather than a set of tunnels, people can share with
each other directly too: your machine and somebody else's see each other the way
two Risc PCs on one office wire did, with ShareFS discs, printers and anything
else RISC OS does over a local network. It can be used at the same time as a
server of your own.

Read the warning in `docs/community-network.md` before turning it on. It is an
open network of strangers, nothing on it is encrypted or authenticated, and
RISC OS's own sharing was designed for a trusted office in the 1990s. A disc you
share there is shared with everybody.

## The Network Analyser

Every Ethernet frame a machine sends or receives can be watched as it happens,
recorded, or handed to another program. There is a window for it in the Manager,
a `rpcemu-netcap` tool for scripting, and the capture can be read by anything
that speaks pcap. The idea is David Ramsden's.

## The OPEN Bus second processor

The Risc PC has a second CPU slot, and 2.0 models it. Six processors are
available for the card:

| | |
| --- | --- |
| 6502 | MOS 6502 and WDC's CMOS 65C02 |
| Z80 | Zilog Z80 and Intel 8080 |
| 68000 | Motorola 68000 |
| 6800 | Motorola 6800 |
| 6809 | Motorola 6809 |
| RV32I | 32-bit RISC-V, base integer set plus M for multiply and divide |

Each has its own page under `docs/`, describing what the card provides and what
a guest has to bring itself.

## Drawing that the host can do

Some of what RISC OS draws, it draws a pixel at a time on the emulated ARM.
Where the work arrives as a SWI and this computer can produce a byte-identical
result, it is done here instead and the guest's code skipped. On by default, and
switched off per machine under *Settings, Machine, System*.

It is deliberately narrow. A scaled sprite plot at 1:1, which is what the
desktop actually does, from a 32bpp or 16bpp sprite, with no colour translation
table, no mask, no alpha and a plain overwrite, onto a framebuffer that is being
scanned out. Anything else falls through to the guest untouched. *Machine
Inspector, Accelerators* shows what was taken and what was not.

## The debugger

Everything in 1.2.0 is here too: the Machine Inspector with FPA registers, every
mode's banked registers, editing registers and memory while stopped, the
disassembly and trace improvements, and the debug socket that gives a script the
same access. See the 1.2.0 notes for the detail.

## Upgrading from 1.x

Machines and configurations are shared between the two, and that is worth
knowing before you run both.

**A 1.x build started on a machine created by 2.0 will quietly drop the settings
it does not understand** - the co-processor card, the network choices, the
capture settings - because it rewrites the configuration from what it holds in
memory when it exits. If you intend to go back and forth, copy the machine's
`.cfg` first. Going forwards only, there is nothing to do: 2.0 reads a 1.x
machine as it stands.

## Downloads

Every archive carries both emulators, on every platform and every architecture.
`rpcemu-recompiler` translates ARM code into your processor's own and is the one
to use; `rpcemu-interpreter` executes one instruction at a time, which is far
slower and exactly what you want when something behaves oddly and you need to
rule the recompiler out.

On Windows and Linux the two sit side by side. On macOS the application runs the
recompiler, and the interpreter is inside the bundle at
`RPCEmu.app/Contents/MacOS/rpcemu-interpreter`.
