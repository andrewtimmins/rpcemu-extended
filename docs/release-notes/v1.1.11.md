One hundred commits since 1.1.10, ten of them from **David Ramsden**, a new contributor
here.

**A fresh installation is no longer a dead end.** RPCEmu ships no ROM and no machine, and
**New...** fetches RISC OS and a ready-made hard disc from RISC OS Open. **Tools → Package
Manager** then installs software from the same repositories a real RISC OS machine uses.

## Getting RISC OS, and software for it

- **Get RISC OS in one step.** Creating a machine offers to fetch a ROM and the ready-made
  HardDisc4 disc from RISC OS Open and set them up on it: 5.30 stable or the 5.31 nightly.
  An existing machine's disc is never overwritten, and nothing is written into place until
  the download and unpacking have both finished. Also available headlessly as
  `--fetch-riscos`, so a scripted or container install works with no display.
- **Whose work it is, acknowledged first.** Before anything is downloaded, RPCEmu shows
  that RISC OS is copyright RISC OS Developments Ltd and developed and maintained by
  RISC OS Open Ltd, reproduces the Apache License 2.0 in full, and asks you to agree. ROOL's
  own copy of the licence is written to the machine's disc alongside the files it covers,
  and there is a button to donate to them. On the command line it is `--accept-licence`.
- **Package manager**, under Tools. Around 200 applications, games, fonts and libraries
  from RISC OS Open and the RISC OS Community, with search, install and remove. Downloads
  are checked against the index's MD5 before anything is unpacked, and what each package
  installed is recorded on that machine's own disc in the RISC OS Packaging Project's
  format, so it removes cleanly and other RISC OS package tools can see it. Also
  `--pkg-list`, `--pkg-info`, `--pkg-install` and `--pkg-remove`.
- **No machine is invented any more.** A machine RPCEmu made up had no ROM and an empty
  disc, so it could not start, and it reappeared every launch however often you deleted it.

## Display and clipboard

- **An emulated graphics card**, with its own 15MB framestore and a GraphicsV driver, so
  modes far beyond what the Risc PC's VRAM allows are available. It converts only the parts
  of the screen that changed, scans out 16bpp, does rectangle copies and fills on the card,
  and carries its state in a snapshot. Its `!GfxCard` utility shows which display is in use.
  With acknowledgement to ViewFinder, whose idea this is.
- **A new machine with the card reads the monitor's EDID**, so it comes up at a sensible
  mode for the screen it is on rather than something arbitrary.
- **Images on the shared clipboard**, as well as text, in both directions: PNG or JPEG,
  passed through as the file both sides already understand. The guest half is RiscOS
  Cloverleaf's own module, built with the Acorn DDE inside the guest.

## Hardware

- **Per-drive IDE registers**, which clears up the phantom ADFS discs. One register file was
  shared between both drives, so selecting an empty drive returned whatever the other had
  left there and RISC OS put a disc on the icon bar that failed on first access. Each drive
  now has its own set and its own ATA or ATAPI reset signature. **The snapshot format goes
  to version 8**; states from 4 to 7 still load.
- **A real serial port on the host.** A USB adapter, a built-in port or a pseudo terminal:
  the speed and framing follow whatever RISC OS programs, and DTR and RTS are mirrored.
  Real hardware is untested, so treat it as new.
- **Print on this computer**, for the parallel port: a finished job goes to a print queue the
  host already has, or to a device such as `/dev/usb/lp0`. This carries the print stream, not
  the port's pins, so IEEE-1284 devices are out of scope.
- **SyncClock**, carried in the expansion ROM, so the clock is right again after a machine
  has been suspended or a saved state resumed later. DEEJ Technology's module, translated
  from their BBC BASIC assembler so it builds with the others. The idea was Nick Brown's,
  from his save-state work.

## Interface

- **The machine editor is five tabs** rather than one very tall column: System, Options,
  Network, IDE Drives and Podules.
- **A restart is offered when a setting needs one** (David Ramsden). Changing a machine's ROM
  and pressing Reset kept the old one, because ROMs are only read at start-up.
- **`--machine`, `--resume` and `--state`** (David Ramsden), with consistent messages and
  exit statuses across all three platforms, and `--machine` now works for the GUI as well as
  headless.
- The About box lists individual attributions rather than a blanket line, and Help gained
  **About RISC OS...**.
- A machine can be set to open automatically at startup, or to start full screen.

## Fixes

- **Creating and cloning a machine on Windows** (#39), where the paths went wrong.
- **The window no longer collapses to nothing** when integer scaling is off (#47).
- **A machine's bridge name no longer turns to rubbish** when its settings are saved
  (David Ramsden).
- **Reduce CPU usage** now raises the graphics card's vsync while idling, which is when
  RISC OS applies pointer and palette changes, and the status bar says "(idle)" rather than
  leaving a MIPS figure near zero looking like a fault. Whether this settles the reported
  pointer lag (#36, #26) wants confirming on real hardware.
- **The emulator was closing its own stdin** at startup, from a zero-initialised socket in
  the TCP modem. Harmless until something else was opened on that descriptor.
- **ShareFS `open` hanging** over NAT, where Access unicasts were being sent twice.
- **macOS**: the shipped `.app` is runnable on a Mac other than the one that built it, and a
  transient `hdiutil` failure no longer loses a whole release.
- Two CVE fragment-reassembly fixes backported into the bundled SLiRP.

## Under the hood

- A **self-contained zip reader** (`src/unzip.c`): its own DEFLATE and CRC-32, no zlib, and
  it understands the Acorn extra field so RISC OS filetypes survive unpacking.
- **MD5** (`src/md5.c`), for checking downloaded packages, verified against RFC 1321's
  vectors.
- The guest-side modules under `riscos-progs/` are built as part of an ordinary build.
- CI now fetches its own cached ROM and boots every platform over VNC to check it reaches a
  desktop; the boot test's ROM and machine stay out of the released archives
  (David Ramsden).
- **MCP**: snapshots usable as an undo, all three mouse buttons, reset, and the clipboard.

## Still open

- **#30**, the arm64 dynarec on Apple Silicon and the arm64 blank screen. The native AArch64
  backend is in the tree and validated under qemu, but the shipped arm64 builds are still the
  interpreter, so this release is unaffected by it.
- **#36 and #26**, pointer lag under Reduce CPU usage. Addressed above, unconfirmed on
  hardware.
